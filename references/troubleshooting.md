# 定位与回滚

先按 [客户端适配](client-adaptation.md) 确认应用/内核与版本。下表 Script.js/merge、YAML、no-resolve 是 Mihomo 分支示例；其他应用检查对应原生配置/转换链，不能硬套这些文件或字段。分层检查 active profile/脚本/实际选择→本地监听→DNS/命中→TCP/UDP/防火墙→TLS/REALITY/认证→资源/进程→目标网站。每次只改一个变量，先留脱敏证据。403/429 不自动归因代理。

| 症状 | 检查 |
|---|---|
| YAML通过但不可用 | 实际请求/出口、认证/目标站，-t 不证明可用 |
| 订阅更新但规则未变 | active profile、Script.js/merge、应用生成/实际运行 |
| 未知国内代理 | 域名是否保留、DNS enable、no-resolve、答案/缓存 |
| QUIC失败TCP成功 | 双向UDP、服务监听、网络限制、TLS/认证 |
| 续期成功TLS失败 | hook日志、公钥配对、权限、重载及实际证书 |
| SSH指纹变化 | 停止并带外核验，不删 known_hosts 绕行 |
| 蜂窝/其他网络订阅或节点失败 | 直接拉订阅 URL 判断入口；手动选 TCP/443 节点测真实出口；按网络路径分层，不先重建 |
| 订阅 200 但客户端解析失败 | 内容截断/格式/客户端版本、节点与组引用、原始 hash；不用“能下载”代替“能导入” |
| 服务端已改但客户端仍旧 | 订阅缓存、profile 是否重新应用、生成配置与运行内核是否一致、核心是否重启 |
| 续期后 TLS 失败 | 合并 PEM、属主/权限、实际 reload/restart、对外提供证书；dry-run 不等于业务成功 |
| provider 缺失/规则变少 | `updatedAt`、缓存、网络、`ruleCount`、首次无缓存；配置解析通过不等于规则完整 |

## 同一配置在不同网络下不一致

校园网/Wi-Fi 可用、蜂窝不可用时，先定位失败阶段，不要先重建服务器或换协议。

1. 在问题网络直接请求订阅 URL（浏览器，或用 stdin/受保护配置传给 curl；不把 URL 交给第三方），记录 DNS/TCP/TLS/HTTP 哪一步失败；超时或重置通常指向订阅入口路径。
2. 在客户端手动选择 TCP/443 + TLS/REALITY 节点，访问显示出口 IP 的公开服务；成功说明节点本身可用，问题在自动选择或其他节点。
3. 逐个测试其余节点；UDP/QUIC、非标准端口、无 TLS 的节点在移动网络更易受限。端口探测全通只证明 TCP 可达，不证明 TLS、协议或应用可用。
4. 已导入配置日常不依赖订阅 URL；更新订阅可先连接可用节点让客户端走代理，或换回稳定网络。
5. 长期把订阅入口迁到域名 + 443（反向代理/CDN/Tunnel 会增加依赖、证书和成本），按生产变更单独批准；不要用关闭证书校验或明文 HTTP 绕过。
6. 记录运营商、网络类型、时间、失败阶段和客户端/内核版本；未在目标网络复测前，不把“改顺序/换节点”标记为已修复。

## 升级后回归

先确认实际运行的二进制、配置、订阅和客户端 profile，不是磁盘上以为的版本。对比变更前后 hash、规则/provider、组选择、DNS、监听、证书和真实请求；失败只恢复最近一个已验证的变更项，不整体覆盖未知旧规则/配置。把“服务 active”当作升级完成，是常见误判。

计划记录每步备份 hash/属主/权限、依赖顺序、恢复时间和验证命令。失败停止后续变更，恢复最近更改的二进制/配置/单元/证书副本/hook；按需 daemon-reload，校验再重启受影响服务。仅撤销本次新增防火墙变更，保护 SSH，不整体覆盖未知旧规则。

恢复订阅和 Nginx，校验/reload后外部拉取。客户端恢复已备份的原生 profile/路由/DNS及订阅来源，通过应用重新加载；Mihomo/Clash Verge 对应恢复 Script.js/merge 并重生成。核对选择、规则/DNS与国内外请求，不覆盖应用生成文件。已暴露并撤销的旧凭据不应重新启用，必要时前滚新凭据。

回滚后查服务/监听/日志、真实出口/请求、旧订阅及清理。记录恢复版本和未解决项；恢复失败停止并留证据，不连续尝试可能破坏管理路径的动作。
