# 多协议部署与故障域

在保留现有可用服务的前提下新增协议。适用于已有 VLESS + REALITY，按需增加 Hysteria2、AnyTLS、Shadowsocks 2022 等；不是所有组合都必须部署，也不以协议数量作为目标。

## 先决条件

- Phase 0 完成：现有服务、配置、订阅、证书、防火墙、监听、资源和回滚点已取证；未知项标 unknown。
- 目标客户端与实际内核已确认；协议/传输/端口/认证在目标版本的支持情况已核对。
- 用户批准覆盖本次具体变更；备份、维护窗口、停止条件和回滚步骤已写入计划。
- 上游版本、安装包/二进制摘要、License 和安全公告已核对；不接受浮动版本或无摘要资产。
- 一次只加一个协议，测通并观察后再加下一个；不迁移或重写原有可用服务。

## 端口、进程与故障域

下表是设计示例，不是固定端口表；按实际客户端、网络和资源调整。

| 入口示例 | 协议 | 传输 | 进程/用户 | 失败域 |
|---|---|---|---|---|
| TCP/443 | VLESS + REALITY | TCP + TLS/REALITY | xray / xray | 仅该进程；通常是保留基线 |
| UDP/443 | Hysteria2 | QUIC/UDP + TLS | hysteria / hysteria | 仅该进程；与 TCP/443 可共存 |
| TCP/8444 | AnyTLS | TCP + TLS | sing-box / sing-box | 与同进程其他入站共享 |
| TCP+UDP/8445 | Shadowsocks 2022 | TCP/UDP，无 TLS | sing-box / sing-box | 与同进程其他入站共享 |

- 同一进程承载多个入站会共享崩溃、重启和资源故障域；这是减少常驻进程的取舍，必须记录。
- TCP 端口开放不代表 UDP/QUIC 可用；UDP 要单独测试双向流量、DNS/QUIC 和应用请求。
- 只开放必要端口；保留管理通道；UFW/nftables 与云防火墙同时核对，不能只看本机。
- 订阅入口（通常 HTTPS/nginx）与节点入口分开规划；不要把订阅端口当作节点端口。

## 证书共享

- 每个服务组使用独立的合并 PEM（`fullchain.pem` + `privkey.pem`），属主 root、属组为该服务用户、权限 640；目录 750，代理用户不可写。
- 续期 deploy hook：在目标目录创建受限临时文件 → 合并 → 分别用 `openssl x509 -pubkey` 与 `openssl pkey -pubout` 提取公钥并比较 SHA256 → 同一文件系统原子 `mv` → 按实际版本 reload/restart。
- Hysteria 可能在每次 TLS 握手重读证书；sing-box 通常需要重启或重载。必须按实际版本验证，不凭经验假定。
- 每个服务单独校验；一个服务替换成功不代表其他服务已加载新证书。
- 续期 hook 失败必须非零退出并保留旧文件；不要打印私钥或完整证书内容。

## 部署顺序

1. **备份与快照**：配置、unit、证书、nginx 站点、订阅文件、UFW/监听、旧凭据位置；验证可读和摘要。
2. **用户与目录**：为每个核心创建独立系统用户（无交互 shell）；配置/证书目录最小权限；systemd 加固（`NoNewPrivileges`、`ProtectSystem`、`PrivateTmp`、最小 capability）。
3. **二进制**：从官方 Release 固定版本和摘要；校验后安装；不使用来源不明的一键脚本。
4. **单协议候选**：先写候选配置并在隔离目录/端口校验；通过后再启动生产 unit。
5. **防火墙**：只新增该协议必要的 TCP/UDP 端口；记录云防火墙和本机规则。
6. **真实握手**：从外部网络做该协议的 TLS/QUIC/认证和真实请求；TCP 探测不能替代。
7. **统一订阅**：保留旧 URL 和旧文件；新增新的精确 location/Token；核对内容 hash、节点数、组引用和兜底。
8. **客户端**：导入/更新、实际节点、出口、UDP/DNS、故障切换；至少目标 Wi-Fi 与蜂窝各一次。
9. **观察**：资源、OOM、日志、证书、订阅更新和故障切换；记录未测项。

## 常见失败

- 配置被 root umask 写成 600，服务用户读不到：改为 `root:<group>` + 640，并检查父目录遍历权限。
- 证书和私钥分文件更新出现错配窗口：合并 PEM + 原子替换；不要先覆盖私钥再覆盖证书。
- 把 Hysteria2 的拥塞控制说成 Linux 内核 BBR：Hysteria 在用户态实现 QUIC 拥塞控制；内核 `tcp_bbr` 只影响 TCP。
- 为降低攻击面关闭 sniff，却仍期望按域名分流：明确取舍并在客户端/规则层验证，不默认开启高风险的 sniff。
- nginx 订阅日志记录完整 URL/Token：`access_log off` 或脱敏格式；Token 不进入 argv、shell history、错误页和公开仓库。
- 新增订阅覆盖旧路径：旧客户端回滚依赖旧 URL；新 Token 使用新精确路径，旧路径保留到获准撤销。
- 只测端口开放或配置校验：它们不能证明 TLS、认证、UDP、路由或应用可用。

## 回滚

- 按协议停用/禁用新增 unit，删除本次新增的防火墙规则，恢复 nginx 站点/订阅，重新 `nginx -t` 和 reload。
- 未修改的旧服务不重启；旧订阅文件/URL 保持可用。
- 保留新增二进制、配置和证书副本以便重新启用；删除或撤销凭据需单独批准。
- 回滚后验证旧订阅 hash、旧节点真实请求、监听/防火墙、客户端选择和 DNS/规则。
- 不能恢复的步骤、未验证项和影响范围写入报告，不把“服务 active”当成业务恢复。
