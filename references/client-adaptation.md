# 客户端确认与适配

先确认用户真正要使用的应用，再决定格式和协议。Mihomo、Xray、sing-box 是内核；Clash Verge Rev、v2rayN、Hiddify 等是应用。应用支持导入某种格式，不代表保留该格式的所有分流、DNS 或扩展语义。

## 首轮交互

涉及客户端交付时，先从本次明确指令、现有上下文和获准的只读信息中提取已知项。不要把 Agent 所在电脑的客户端推定为用户手机或其他设备的目标。缺失时合并成一个简短问题：

> 准备在哪些设备和客户端使用？可以多选，例如 Windows + v2rayN、Android + Hiddify、iPhone + Shadowrocket；需要只导入节点，还是连分流和 DNS 一起配置？不清楚客户端名称也可以先说设备。

使用当前可用的交互提问工具，保留自由输入；界面选项不能代替记录多设备需求。没有工具就普通对话提问。客户端选择未回答前不生成最终配置、不据此修改生产；可以继续服务器只读取证。等待时间不构成答案。版本缺失时帮助查看“关于”或读取当前内核，不索要账号口令、含凭据的订阅 URL 或完整截图。

客户端明确后，仅追问影响当前任务的缺失项：应用版本、实际内核及版本、节点或完整配置、是否保留原路由/DNS、系统代理/TUN/VPN 模式、订阅更新需求。用户只要节点时，不强行要求设计全套 DNS。只读服务器审计可以客户端未知，报告“客户端适配未评估”。若本次任务仅更新 Skill 本身，不把示例中的问题误当成必须向维护者索要真实客户端。

不知道选哪种客户端时，按设备、是否已安装、费用意愿和需要的协议核对官方资料，提供少量可行选择与差异供用户决定；不擅自购买、安装或切换。简称/错拼不能自动落到某个内核。

## 适配记录与选择门槛

每个目标单独记录以下字段，普通文档不含服务器地址或凭据：

| 字段 | 内容 |
|---|---|
| 目标 | 设备别名、系统/版本、应用/版本、内核/版本或内核不可见 |
| 交付 | 节点链接、节点订阅、完整配置；本地导入或 HTTPS 更新 |
| 能力矩阵 | 协议及参数、TCP/UDP、TLS/REALITY、认证、DNS、规则、手动选择/测速/故障切换 |
| 依据 | 官方文档/Release/tag/日期、该版本实测或待验证 |
| 不兼容项 | 明确不支持、未核实、仅节点可导入、规则需另配；用户选择的处理方法 |
| 验收 | 原生检查、真实应用导入/重载、节点数、连接/路由、更新持久化与回滚 |

服务端和所有目标客户端的协议交集决定通用节点；设备专属协议可额外输出，但要解释范围。不能把“不知道支持”当成“不支持”，也不能为让配置导入成功而静默删除认证/TLS/UDP 参数。确有缺口时，提供已部署的兼容节点、经确认的升级/换客户端或新增兼容协议方案；新增服务仍按原生产权限流程。

## 分支工作流

下表是适配路径，不是永久的协议支持列表。每次按目标版本查询原生格式与限制。

| 目标 | 配置与导入处理 | 验证重点 |
|---|---|---|
| Clash Verge Rev / 其他 Mihomo 前端 | Mihomo YAML；检查应用自己的 merge/覆写/脚本能力，再使用 mihomo-routing.md。Script.js 只在应用确实支持时交付 | 实际内核 -t、应用生成配置与运行配置、规则/provider、DNS和组当前选择；服务模式/pipe 见 mihomo-routing.md |
| v2rayN | 根据实际版本的导入器生成支持的节点分享链接/订阅；确定每种节点实际选用的核心。需要自定义完整配置时走应用提供的对应入口，不能把核心 JSON 自动当成通用订阅 | 应用导入结果与核心映射、原生路由/DNS是否保留、更新是否覆盖设置；校验实际生成的核心配置 |
| v2rayNG | 按 Android 应用版本及实际核心选择分享链接/订阅或其支持的自定义配置入口；路由/DNS单独处理 | 手机上的导入与实际 VPN 请求、支持的传输参数、原设置/更新；不能沿用 v2rayN 的菜单与多核心能力假设 |
| 原生 sing-box 客户端 | 为目标版本生成 sing-box JSON，使用原生 outbounds/route/dns；按官方迁移指南处理版本变化 | 对应二进制 check（可用时）、目标应用加载、路由与 DNS；不能直接塞入 Clash YAML |
| Hiddify | 核对应用版本支持的导入格式、内置核心及本地覆盖方式；选择经验证的输入格式 | 导入器是否重写路由/DNS、节点参数是否完整、更新后的实际行为；不能因可导入 Clash 就假定所有 Clash 语义保留 |
| Shadowrocket | 根据应用版本、开发者说明/官方发布记录与设备导入结果选择节点链接、订阅或原生配置 | 分清节点订阅与规则配置；核心不可见时注明，不猜版本；需目标设备验证协议参数、DNS、实际请求和更新 |
| Surge / Quantumult X | 分别查产品和平台版本的原生 profile/节点资源/规则资源规范，分别生成，不共用一份未经验证的 Apple 客户端格式 | 协议、策略组、最终兜底、DNS与远程资源是否原生支持；不能直接搬用 Mihomo YAML/MRS/Script.js |
| OpenClash / 路由器插件 | 先确认插件、路由器系统、核心和资源，按该插件订阅/覆写流程适配 | 管理连接、LAN DNS、透明代理/转发、插件重载覆盖；不能套用桌面 TUN/系统代理操作 |
| 其他客户端 | 查应用官方资料/导入器格式，补充上述适配记录后再生成 | 找不到可靠依据则标待验证，不输出“全兼容”结果 |

v2rayN/v2rayNG 不等于某个固定核心；目标设备必须实查。WireGuard 等专用客户端走其原生配置与隧道路由，不承诺节点分享订阅、应用规则组或自动切换与 Mihomo 等价。

## 原生策略转换与输出

先抽象用户要的行为：手动选节点、按延迟选择、顺序故障切换、国内直连、未知海外走代理。再映射到目标应用的原生能力。Mihomo 的 select/url-test/fallback、MATCH,PROXY、rule-providers/MRS、no-resolve、nameserver-policy 都不能原样用于所有客户端。Surge 用其原生 FINAL 规则，sing-box 用其版本支持的 route 最终出站；其他格式按官方语义实现。无原生等价能力时说明差异并让用户决定，不用“转换成功”掩盖功能损失。

从同一受保护节点数据生成各目标输出，记录节点及参数映射；多格式可用不同受保护 HTTPS 路径，不靠不稳定的 User-Agent 猜测输出。保持各自更新入口和旧订阅回滚，新增路径仍需批准。不能覆盖用户已有路由/DNS，也不能把节点订阅说成完整配置。转换器本地/自管运行并固定版本，不把秘密交给公共转换服务。

## 逐客户端验收与交付

1. 先生成独立候选和语义差异；检查支持/不支持/待验证节点列表、参数完整性、策略引用、DNS与兜底。
2. 有对应内核时使用 config-validation.py 的 Mihomo/Xray/sing-box 分支，提供实际二进制及隔离目录；不能用 Xray -test 代替 Shadowrocket/Surge 等应用导入验证。配置检查可能联网写缓存，不能误标无副作用。
3. 先备份原 profile/订阅、选择、路由/DNS和网络模式并确认可恢复，再按目标应用的实际入口导入独立候选或测试 profile，核对节点数、协议和参数。切换当前 profile、覆盖设置或更改系统代理/TUN/VPN/路由需属于批准范围。
4. 每设备验证真实连接、出口、必要 UDP/DNS、国内/海外命中与应用访问；有能力的策略再测测速/切换。无桌面 controller 的移动端使用其诊断/请求日志，不硬调用 Mihomo API。
5. 执行一次订阅更新或配置重载，确认节点、路由、DNS和选择是否按预期保留。仅导入成功不算完整支持。若客户端仍显示旧内容，检查订阅缓存、profile 是否重新应用、生成配置与运行内核是否一致。
6. 无目标设备或无法控制该应用时交付候选及具体操作步骤，标“待设备导入/实连验证”，让用户反馈脱敏错误或结果；不能伪造 GUI/移动端实测。回滚恢复原生 profile/订阅来源/设置，通过应用重新加载。
7. 在目标设备的实际接入网络验收：至少 Wi-Fi 与蜂窝各一次，包含订阅首次导入/更新、手动选点、真实出口和必要 UDP/DNS；只在一个网络通过不能标记为移动可用。失败按 [troubleshooting.md](troubleshooting.md) 的网络路径分层，不先改服务器。

最终按设备给出：支持哪些节点、输出文件/受保护订阅位置、导入及更新步骤、分流/DNS是保留还是替换、验证证据/未测项、回滚步骤。不能只交付一份通用 YAML 后宣布所有客户端完成。
