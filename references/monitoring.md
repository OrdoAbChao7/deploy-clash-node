# 监控、健康检查与资源

服务/进程、网络路径、应用层分开记录；前一层不能替代后一层。本机通过代理的检查只代表当前网络和当前选择。

## 分层检查

| 层 | 检查 | 不能证明 |
|---|---|---|
| 服务 | unit active、监听、权限、日志、OOM、证书期限、磁盘 | 外部可达、协议正确 |
| 网络路径 | 订阅入口、节点 TCP/UDP/TLS/QUIC、DNS、Wi-Fi/蜂窝/企业网 | 应用认证、规则命中 |
| 应用 | 真实请求、出口 IP、规则/chains、客户端导入/更新 | 长期稳定、所有网络可用 |

## 连续检测

- 只读脚本按固定间隔检查：配置/订阅 hash、运行规则/provider、DNS、节点延迟、系统代理/TUN、关键站点；输出当前状态、历史记录和告警。
- 成功不刷屏；失败去重；恢复后清除告警。告警渠道要验证可达，写入文件或 syslog 不等于用户收到。
- 记录时间、网络标签、客户端/内核版本和失败阶段；至少在目标 Wi-Fi 与蜂窝分别执行。本地 PASS 不能推断其他网络可用。
- 检测脚本不自动修改生产、重启服务或切换节点；修复需要单独批准。脚本自身的路径、权限和依赖也要纳入维护。
- 订阅入口与节点连接分开测：订阅 URL 可能被运营商/企业网阻断，已导入配置仍可日常使用；不要因更新失败重建服务器。

## 流量与资源

只读检查 vnStat 是否存在、数据库起点、接口、统计空窗；未安装不能宣称全月统计。安装/timer/通知配置属于生产变更。监控 CPU/RAM/Swap/OOM/cgroup/网卡 RX/TX，共享核心内存不按协议臆拆。

vnStat 与服务商账单分别记录窗口、入出方向、单位、实例/账户范围、账期/时区、共享规则、额度/超额价和来源。Vultr 等必须核对控制台、官方文档或 API；metadata/本机用量不证明套餐。额度未知报告 unknown，不输出假百分比。

核实后按实际计费方向/周期设 70% 提醒、85% 高、95% 严重；记录已通知等级避免重复，账期重置后清零。验证通知可达，写 syslog 不等于用户收到。阈值不授权自动停服、限速、购买流量或升级套餐。

接入网络也是监控维度：本机通过 127.0.0.1 代理的健康检查只代表当前网络和当前选择。至少记录一次目标 Wi-Fi 与蜂窝网络下的订阅更新、手动选点、真实出口和关键站点结果；不要用本地 PASS 推断所有网络可用。跨网络失败先按 [troubleshooting.md](troubleshooting.md) 分层，不把端口探测或配置校验当成应用层可用。
