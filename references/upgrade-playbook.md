# 既有部署升级与迁移

用于升级二进制、配置、协议、订阅、规则/DNS 或客户端 profile。升级不是重装：先只读取证，再候选、批准、逐项实施、验证和回滚。

## 变更分类

| 类型 | 主要风险 | 最低验证 |
|---|---|---|
| 二进制/核心升级 | 配置不兼容、行为变化、回滚困难 | 官方 Release/公告、隔离配置校验、真实请求、旧二进制回滚 |
| 配置/端口变更 | 服务中断、防火墙/客户端不同步 | diff、候选校验、监听、外部握手、客户端更新 |
| 新增协议 | 资源、证书、UDP、故障域扩大 | 单协议部署、真实握手、故障切换、回滚 |
| 订阅迁移 | 旧客户端失效、Token 泄漏 | 新路径/旧路径并存、hash、客户端导入/更新、日志审计 |
| 规则/DNS 迁移 | 误直连/误代理、DNS 泄漏、循环 | 候选脚本、隔离 Mihomo、样本命中、diff、生产回滚 |
| 客户端升级 | 设置被覆盖、格式不兼容 | 备份 profile/订阅/选择、实际导入、节点/规则/DNS 核对 |

## 通用步骤

1. **盘点**：当前版本、配置、订阅、证书、防火墙、监听、客户端、资源和最近变更；未知项标 unknown。
2. **调研**：目标版本官方 Release/提交/Issue/安全公告/License；确认目标客户端和核心的兼容性。
3. **备份**：配置、二进制、unit、证书副本/hook、nginx、订阅、规则/脚本、客户端 profile；验证可读和摘要。
4. **候选**：在隔离目录/端口/核心生成并校验；不直接改生产，不手改应用生成文件。
5. **批准**：给出 diff、影响面、维护窗口、停止条件、逐项回滚和预算；生产变更需覆盖具体变更的批准。
6. **逐项实施**：一次只改一个变量；每步完成 active/监听/日志/真实请求后再继续；失败停止并恢复该步。
7. **客户端**：更新/重载、节点/组/规则/DNS/出口、订阅更新持久化；至少目标 Wi-Fi 与蜂窝各一次。
8. **观察**：24–48 小时资源、OOM、证书、provider 更新、错误日志和故障切换；记录未测项。

## 规则/DNS 迁移（Mihomo 分支）

- 生产 Script.js/merge → 独立候选 → 实际输入转换 → 隔离 Mihomo → diff 与样本测试 → 用户批准 → 更新生产脚本 → 应用重生成 → 运行内核核对。
- 不直接编辑生成的 `clash-verge.yaml`；保留旧脚本、旧选择和回滚备份。
- 验证国内、未收录国内、未收录海外、AI/OAuth、开发依赖/镜像和最终兜底；规则数量不是目标。
- 明确“忠实迁移”与“优化”的区别；未知海外默认代理，不用 REJECT 兜底；策略变化写入 diff。
- 系统代理模式下应用自行解析的 DNS 可能绕过 Mihomo DNS；记录限制，不承诺零泄漏。

## 订阅迁移

- 新 Token 使用新精确路径，旧路径和旧文件保留至少一个稳定周期；不得覆盖旧订阅。
- 比较原始内容 hash、节点数、组引用、规则和兜底；外部拉取验证，不只回环自测。
- 订阅日志禁用或脱敏；URL 只存受保护文件，经 stdin/受保护 curl 配置传递，不进入 argv。
- 客户端导入/更新后核对节点、组顺序、当前选择、出口和更新持久化；旧 URL 作为回滚。
- 撤销旧 Token 需单独批准并确认旧客户端影响。

## 客户端 profile 升级

- 先备份原生 profile/订阅来源/选择/路由/DNS/系统代理或 TUN/VPN 模式；确认可恢复。
- 生成独立候选，按目标应用实际导入器/内核校验；不只复制一份通用 YAML。
- 导入后核对节点数、协议参数、策略组、规则、DNS 和实际请求；执行一次订阅更新/重载，确认设置不被覆盖。
- 回滚恢复原 profile/订阅来源并通过应用重新加载；不手改应用生成文件。

## 停止条件

- SSH/管理通道异常、证书或私钥错配、生产真实请求失败、客户端大面积不可用、超出流量/时间预算。
- 停止后续变更，恢复最近一个已验证的回滚点；不连续尝试高风险绕行，不把“服务 active”当成业务恢复。
- 记录失败阶段、证据、已回滚/未回滚项和后续待验证；需要新授权时停下来。
