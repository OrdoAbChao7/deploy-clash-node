# 校园网/企业认证门户直连

适用于目标接入网络需要网页登录（校园网、企业、酒店等 captive portal），或认证/自助服务站点位于私网地址段。不同学校/企业的门户地址和域名各不相同，**本 Skill 不预置、不沿用任何具体 IP 或域名**；先交互确认是否需要该模式，再按用户确认的实际地址落地。

## 先交互确认

涉及部署、分流优化或“节点全不可用”排障时，若接入网络可能是校园网/企业网，先问：

> 目标接入网络是否需要网页认证门户（校园网/公司/酒店）？需要的话，请提供门户/认证服务器的 IP 或网段，以及认证、自助服务使用的域名后缀。

按回答分支：

1. **是**：收集并核对
   - 门户/认证服务器地址（IP 或 CIDR，常见为私网，如 `172.x`、`10.x`；以门户页实际地址、`ip route` 或用户提供为准）；
   - 认证/自助服务域名后缀（只收用户确认的域名；不默认把整个教育域或公司域直连）；
   - 认证发生在哪一层：路由器/网关 WAN 侧认证，还是本机直接接入；
   - 是否存在其他接入网络（Wi-Fi/蜂窝），规则只应作用于需要认证的那条路径。
2. **否**：不加任何校园门户规则，按普通分流处理。
3. **不确定**：先只读取证——打开任意 HTTP 目标看是否跳登录页、记录门户 URL/地址、检查路由与 DNS；仍无法判断时保持问题待答，不按猜测直连私网段或域名。

确认结果（网络类型、地址段、域名、认证层）写入交付说明。换学校、换网络时重新确认，不复制他处规则。

## 规则

目标：让门户登录、认证和自助服务流量绕过代理与 TUN，直接走本地 WAN；同时不扩大直连范围。

Mihomo（TUN 模式）示例，尖括号处替换为用户确认值：

```yaml
tun:
  route-exclude-address:
    - <portal-cidr>          # 门户/认证私网段，避免被 TUN 捕获
rules:
  - IP-CIDR,<portal-cidr>,DIRECT,no-resolve   # 放在代理与国内规则之前
  - DOMAIN-SUFFIX,<auth-domain>,DIRECT        # 认证/自助域名
```

- 私网段规则用 `no-resolve`，避免域名被 DNS 解析进 IP 规则造成误判；
- 只直连确认过的门户地址段与认证/自助域名；不把 `0.0.0.0/8` 等大段私网或整个教育域/公司域直连；
- 门户直连规则置于私网直连之后、代理与国内分类规则之前，保持原有兜底语义；
- 认证站点即使解析到公网，也应显式 `DIRECT`，否则会被 TUN/`MATCH,PROXY` 送进海外节点，门户按海外来源重置连接；
- 其他客户端用其原生等价语法（v2rayN 路由规则、sing-box `route.rules` 等），不复制 Mihomo 字段；无法表达时说明替代方案，不静默丢弃。

## 验证

1. 打开用户确认的门户 URL，应返回登录页，而不是 `ERR_CONNECTION_RESET`/超时；
2. 登录成功后做节点延迟测试：返回 delay，之前的 `x509: certificate is not valid for any names` 等错误消失；
3. `ip route get <门户 IP>` 显示走 WAN 接口而非 tun；
4. 认证域名 DNS 返回 `198.18.x`（fake-ip）属正常现象，连接时按 `DOMAIN-SUFFIX ... DIRECT` 直连，不以 DNS 结果判断泄漏；
5. 用真实请求核对命中（Mihomo connections 的 rule/chains），不只依赖配置解析通过。

## 维护与回滚

- 门户会话绑定 WAN IP；路由器重启、DHCP 续租或门户超时后可能重新要求登录。交付说明记录门户 URL，便于用户自行重新登录；
- ICMP 常被禁用，不用 ping 网关作为唯一检查；
- 规则变更保留备份与 hash；回滚时移除新增的 `route-exclude-address`、`IP-CIDR`、`DOMAIN-SUFFIX` 条目，恢复配置后重载，再核对门户与节点；
- 不要把门户凭据、会话 Cookie 写入配置、日志或 Skill。
